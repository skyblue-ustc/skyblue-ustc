# 每周技术复盘

围绕一个真实问题，留下可核验的代码、实验和判断。这里收录完成验证后整理的技术记录；当前先建立写作模板。

## 每周怎么写

选择一次代码阅读、复现实验、故障排查或开源贡献，控制在一页；结论不确定时明确记录，不必每周追求新功能。建议命名：`YYYY-MM-DD-topic.md`。

## 一页模板

```markdown
# 日期：具体技术问题

## 问题与假设
场景是什么？我预期什么？什么结果会否定这个判断？

## 代码链路
入口 → 关键函数 → 状态变化 → 输出。附版本与代码永久链接。

## 实验与证据
- 代码 commit、模型和依赖版本：
- 数据来源、划分与随机种子：
- 基线、改动、预算与运行命令：
- 结果：任务表现、成本、重复运行波动。

## 失败与解释
一个关键失败案例；已经确认的原因；仍待验证的解释。

## 结论与下一步
这次证据支持什么，不支持什么？下周只验证哪一个问题？

## 相关链接
代码 / 实验配置 / issue / PR / 参考论文。
```

## 公开前检查

- 只发布可公开的代码、数据与实验记录，使用公开或自行构造的复现案例。
- 区分个人实现、上游方法和团队成果。
- 报告指标时交代基线、样本和条件；区分观察与推测。
- issue / PR 记录注明当前状态，不把待审修改写成已合并贡献。
